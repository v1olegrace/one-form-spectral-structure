The numerical diff guard above included `output/figures` and all of

possible and untested here; the first remote run will show them.

## Addendum, 23 October 2026, afternoon (R3)

The independent review pointed out that excluding `extended_verification.json`
from the byte guard leaves it unchecked. It is now checked semantically:
`scripts/compare_extended_verification.py` compares the regenerated file with
the committed one.

- It skips only the `environment` block and keys ending in `_error_estimate`.
- Every other value must be equal exactly. There are no tolerances.

This matches the clean-room evidence. The first clean-room file differs byte
for byte from the working tree, yet has 0 scientific differences under this
definition.

CI runs the comparator after `make.py numerics`, against
`git show HEAD:output/data/extended_verification.json`. A test asserts both
the CI step and the comparator's behaviour: it accepts changed versions and
error estimates, and reports a 1e-15 change in a result.

## Addendum 2, 23 October 2026, night (R6)

The first Ubuntu 24.04 run (WSL, same package versions) found real
cross-platform drift in three byte-guarded files:

- the float64 round-off diagnostics `float64_relative_difference` in
  `localizing_bounds.csv` and `verification_checks.json` (5.90e-12 against
  4.81e-12);
- one Monte Carlo RMSE in `uncertainty_summary.json`, by 1 ulp.

The comparator was renamed `scripts/compare_numerical_outputs.py` and
extended to JSON and CSV. It skips round-off diagnostics, versions and error
estimates, and compares every other float to within 8 ulp. The three files
moved from the byte guard to the comparator. The paper figures' data files
stayed byte-identical across platforms.

The second Ubuntu run used blobs normalized to LF, as git stores them with
`core.autocrlf=true`. It found that Python's `csv` module writes CRLF on
every platform, so every generated CSV differed from its LF blob on Linux,
in the numerics guard and in the audit-ledger guard alike. Both guards now
use `git diff --ignore-cr-at-eol --exit-code`. Tested with git 2.43 on
Ubuntu: it exits 0 when only line endings differ and 1 when content drifts.
