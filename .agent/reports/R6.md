## What the Ubuntu runs found, and the fixes

**First run.** The snapshot was copied with CRLF bytes and
`autocrlf=false`. Ignoring line endings, three guarded files differed
between Windows and Linux:

- `localizing_bounds.csv` and `verification_checks.json`: the
  `float64_relative_difference` diagnostics, whose value is a float64
  rounding error (5.90e-12 against 4.81e-12);
- `uncertainty_summary.json`: one Monte Carlo RMSE, by 1 ulp.

The paper figures' data files were identical. The fix was the comparator
`scripts/compare_numerical_outputs.py`. It skips round-off diagnostics,
versions and error estimates, and compares every other float to 8 ulp;
these files left the byte guard.

**Second run.** The snapshot was rebuilt with LF blobs, as the real
repository has. Python's `csv` module writes CRLF on every platform, so
every generated CSV differed from its LF blob on Linux. This affected the
numerics guard and the audit guard, which was added in P4 and has never run
in CI. The fix is `git diff --ignore-cr-at-eol --exit-code` in both guards.
On git 2.43 it exits 0 for line endings only and 1 for content.

Without these two fixes, the first push would have failed in CI at the
numerics guard and at the audit guard.
